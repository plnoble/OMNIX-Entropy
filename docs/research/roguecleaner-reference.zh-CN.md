## 值得吸收

- 不只看“安装了什么”，还看软件把自己放进了哪些 Windows 入口。
- 把技术位置翻译为“右键菜单、开机启动、后台服务、计划任务、浏览器连接、文件打开方式”。
- 清理前保留证据和备份，处理后逐项复核并再次扫描。
- 默认不勾选，不把默认打开程序、隐藏组件或正在运行进程直接当作可清理项。
- 原厂卸载器与残留处理分开，卸载完成后再检查当前状态。

## 本次采用

OMNIX 新增只读“软件系统足迹”：

- 右键菜单。
- “此电脑”及资源管理器入口。
- Chrome、Edge、Firefox 的 Native Messaging Host 注册。
- 常见文件类型的默认程序与“打开方式”线索。

归属只使用安装路径或完整应用名证据，不使用品牌黑名单给软件定罪。应用抽屉显示数量和入口类型，原始注册表位置只在技术详情中展示。系统足迹不会产生删除、禁用或卸载操作。

## 明确不采用

- 不复制上游内置厂商和“坏组件”关键词表。
- 不把命中品牌、名称或关键词直接换算成风险分数。
- 不新增直接删除注册表、禁用服务、禁用计划任务或强杀进程的旁路。
- 不因为 MIT 许可就混入上游源码；若未来确需复用，必须单独做来源标注、许可证保留和安全审查。
- 不采用自替换更新器或单文件架构作为当前 OMNIX 发布方案。

## 后续候选

1. 官方卸载后，把系统足迹也纳入只读复扫，说明还有哪些入口没有消失。
2. 为单个入口提供“让 Agent 解释”，区分有用入口、可关闭入口和归属不确定入口。
3. 只有具备当前状态快照、精确目标、回滚证据和 `OperationPipeline` 确认时，才评估单项处理；品牌或关键词永远不能单独授权执行。
